# Интеграции gpux: AI Horde, ComfyUI-Distributed и производные

Разбор от 2026-09-07. Вопрос: как gpux встраивается в эти проекты и как они — в наш пайп.

---

## 0. Наш пайп — инварианты (то, что интеграции не должны ломать)

1. **Тёплая нода.** Модель живёт в VRAM, init единожды (~30s). Любая интеграция,
   заставляющая ноду перезагружать модели на каждую задачу, — регресс.
2. **Доверенная среда.** Tailscale, свои машины, basic auth. Никаких чужих машин
   в дефолтной топологии.
3. **Живой стрим.** SSE: фазы, шаги, превью в реальном времени. Асинхронный
   «отправил-и-ушёл» — дополнение, не замена.
4. **Sticky jobs.** Прогресс/превью от той же ноды, что выполняет задачу.
5. **Тонкий роутер.** Состояние живёт в нодах; роутер маршрутизирует и агрегирует.
6. **Видео — наш козырь.** WanGP даёт Wan/LTX/H3-видео, которого нет ни у Horde,
   ни в ComfyUI-экосистеме из коробки. Сдавать эту позицию нельзя.

## 1. AI Horde (Haidra-Org/AI-Horde)

**Что это фактически:** центральный доверенный координатор (бридж) + воркеры
добровольцев + экономика kudos. Enterprise-grade ML-Ops middleware с
drop-in/drop-out воркеров. Публичный кластер aihorde.net + опенсорсный сервер
для приватных деплоев. Image (SD-family) + text (LLM). Kudos: заработал
ресурсом → получил приоритет; **покупка/продажа kudos запрещена ToS**.

**Интеграция «в наш пайп» (мы отдаём ресурс):**
- Паттерн **idle-worker**: когда gpux-нода N минут не получает задач от
  роутера, она регистрируется воркером в публичной Horde и фармит kudos;
  первая юзерская задача → deregister → тёплая генерация. Нода монетизирует
  простой, не мешая основной функции.
- Технически: рядом с WanGP поднимается `horde-worker-reGen` (SD-стек),
  НЕ внутри WanGP. Horde не умеет Wan/LTX/H3 — видео-нода в idle-mode может
  фармить только если на ней стоит SDXL/Flux-стек рядом.
- Приватность: чужие промпты видны воркеру. Для наших машин это осознанный
  режим, не дефолт.

**Интеграция «нашего пайпа с Horde» (мы потребляем):**
- **Horde как backend-тип ноды в роутере** (`backend: horde`): все свои GPU
  заняты → эластичный перелив в публичную Horde (async: submit → poll).
  Годится для черновиков; для чистовика — свои GPU.
- **Kudos-фарм связывает всё:** ноды фармят kudos в простое → аккаунт роутера
  тратит их на overflow-запросы. Получается замкнутая экономика: простой
  конвертируется в приоритет elsewhere. Это прототип тезиса prolog-bc/DePIN
  «неиспользуемый ресурс = токен», только в валют Horde.
- **Приватный Horde — НЕ поднимаем.** Их сервер заменит наш роутер, а не
  дополнит; мы потеряем стрим/превью/tailscale-топологию и получим чужой
  монолит. Берём идею kudos (учёт вклад/потребление в своей sqlite),
  не код.

**Вердикт:** Horde = L0 (экономика) и эластичный Overflow-пул. Не конкурент
нашему L2/L3.

## 2. ComfyUI-Distributed (robertvoy/ComfyUI-Distributed)

**Что это фактически:** extension для ComfyUI, распределяющий выполнение
ОДНОГО воркфлоу по нескольким ComfyUI-инстансам (локальные/сетевые/облачные
воркеры): параллельные сиды, distributed upscaling тайлами, сбор результата
на мастере. Требует ComfyUI на каждой ноде и --enable-cors-header на мастере.

**Ключевое различие с gpux — гранулярность:**
- gpux роутит **задачи юзера** (целый запрос → свободная нода).
- ComfyUI-Distributed роутит **куски воркфлоу** (одна задача → параллельно).

**Интеграция:**
- Прямая — не нужна: два мультиплексора одного уровня конфликтуют. Если на
  нодах появится ComfyUI как второй движок, наш роутер шлёт целые воркфлоу
  на свободную ноду (ComfyUI-API на каждой ноде + наш node-адаптер).
- Их сценарий нам пригодится позже: **видео-апскейл длинного ролика тайлами
  на нескольких GPU** — тогда встраиваем по умному, но это L1-оптимизация,
  не L3.

**Вердикт:** не интегрируем; фиксируем как future-паттерн для intra-job
параллелизма.

## 3. comfyui-api (Hardonian) и sd-webui-distributed (papuSpartan)

**comfyui-api:** Cloudflare Workers gateway + D1-очередь + lease-воркеры +
dashboard. Для нас — **источник архитектурных паттернов**, не код:
- lease-модель: воркер сам забирает задачу из очереди (решает проблему
  «роутер не знает, что модель уже в VRAM»);
- версионированные шаблоны воркфлоу;
- API-ключи, rate limits, роли.
- Runtime (Cloudflare D1) нам не подходит — у нас доверенная сеть и стрим.

**sd-webui-distributed:** master/slave для A1111, требует одинаковые модели
на слейвах. Для нас — **анти-паттерн**: принудительная гомогенность нод
противоречит принципу «нода = её модели, роутер знает capabilities».

## 4. Синтез: слои и точки приклейки

```
L4  юзеры/морды      gpux web, позже TG-бот
L3  мультиплексор    gpux router (sticky, стрим, health)
L2  worker-протокол  gpux node API v0 → v1 (capabilities)
L1  движки           WanGP (видео/flux/TTS) · ComfyUI (SDXL-экосистема) ·
                     horde-worker-reGen (SD в idle) · Horde API (overflow)
L0  экономика        свой учёт вклада/потребления → проецируется на prolog-bc
```

**Принцип:** gpux — это L2/L3. Мы не становимся Horde (L0) и не становимся
ComfyUI (L1). Мы — тонкий доверенный мультиплексор над разнородными движками.

**Пустота, которую закрывает L2-v1 (сначала):** capability-эндпоинт ноды —
какие движки/модели/объёмы VRAM у неё есть. Без него роутер не может
маршрутизировать по типу задачи (видео → WanGP-нода, SDXL-воркфлоу →
ComfyUI-нода, черновик → Horde).

## 5. Последовательность действий (малые шаги)

1. **Node Protocol v1**: `/api/capabilities` на ноде (движки, модели, VRAM,
   скорость, backend-тип) + роутер маршрутизирует по capabilities. ~1 вечер.
2. **Учёт в роутере**: sqlite — юзер, время, нода, шаги, длительность.
   Фундамент экономики (наш аналог kudos). ~1 вечер.
3. **Horde-adapter** в роутере (`backend: horde`, async submit/poll,
   отдельный тег «черновое качество»). ~1-2 дня.
4. **Idle-mode ноды** (horde-worker-reGen рядом, вкл/выкл по idle-таймеру,
   дренаж очереди перед выходом). Опционально, после 1-3.
5. **ComfyUI-адаптер ноды** — когда появится реальная задача под SDXL.
6. **Не делать:** свой Horde-сервер; ComfyUI-Distributed в стек; требование
   одинаковых моделей на нодах.

## 6. Риски

- **ToS Horde:** kudos нельзя покупать/продавать/конвертировать. Фармить
  своим железом и тратить на свою генерацию — легально. Мост «kudos → токены
  prolog-bc» — ЗАПРЕЩЁН; токенная экономика строится параллельно и только
  внутри своей инфры.
- **Приватность:** overflow в Horde отправляет промпты на чужие машины.
  По умолчанию off; включается per-запрос флагом «черновик».
- **Дрейф моделей:** Horde и наши ноды — разные наборы; overflow-результат
  не воспроизводит нодовый. Фиксировать в metadata артефакта, где считалось.
